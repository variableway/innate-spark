# T09 — 注册表生成脚本（bun 版 plot 接缝）

> **状态：已完成（2026-09-16）**
> 阶段：P3 · 独立任务。脚本的输入只是"目录约定"，可用夹具目录独立开发测试，不依赖真实 domain 存在。

## 目的

用 **bun + TS** 实现 cycle 中由私有工具 plot 承担的"接缝生成"：扫描 `domains/` 目录，生成两个聚合文件——`apps/webshell/src/plugins/modules.gen.ts`（import 全部 `webDomain` 并导出数组）与 `styles.gen.css`（按 base→domain→app 固定顺序聚合各包 `globals.css`）。宿主手写代码从此不被插件增删触碰。

## Context

- 参照 cycle：`vineModules.gen.ts`（import 每个 domain 的 webDomain，导出 webModules 数组）与 `vineStyles.gen.css`（base → domain → app 顺序聚合）两个生成文件 + gitignore + 禁改约定（`cycle-all/cyacle/change.web.md:29-52`）；该设计动机是"宿主手写代码不被模板覆盖"。
- 本仓差异：cycle 由闭源 plot 生成；我们用 bun 脚本（overview 目标 5/6：脚本化、基于 bun/ts、实现在 base-fe）。脚本位置：innate-fe-base 根 `tools/gen/registry.ts`（或 webshell `scripts/`），由 `bun run` 直接执行 TS。
- 输入约定（由 T04 确立）：`domains/<name>/package.json` 存在且 `name` 以 `@innate/domain-` 开头、`src/index.ts` 导出 `webDomain`、`exports['./globals.css']` 存在（缺失则样式聚合跳过该包并 warn）。

## 实现方式

1. `scan`：读 `domains/*/package.json` 过滤合法插件包，输出内存 manifest（id、包名、路径、顺序权重可选字段 `pluginOrder`）。
2. `gen modules`：产出稳定排序（字母序 + pluginOrder 覆盖）的 import 列表与 `export const webModules = [...]`；文件头带 `// @generated by tools/gen — DO NOT EDIT`。
3. `gen styles`：`@import` 序列 = `@innate/ui/globals.css`（base）→ 各 domain `globals.css` →（webshell 自身 css 由 app 侧最后 import，不进生成文件，保持 cycle 的"app 是最终覆盖层"语义）。
4. `--check` 模式：CI 用——重新生成并与磁盘对比，不一致即非零退出（防止手改生成文件）。
5. watch 模式（可选）：`--watch` 监听 domains 目录增删自动重生成，本地 dev 时省一步。
6. 单测（bun test）：夹具目录 → 快照断言生成内容；非法包（无 webDomain 导出、缺 package.json）被跳过并记录。
