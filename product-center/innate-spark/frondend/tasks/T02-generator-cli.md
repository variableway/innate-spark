# T02 — 生成器 CLI（gen / build / verify 骨架）

- **阶段**：P0　**前置**：无（gen 的最小实现不依赖 T01；完整实现消费 T01 的类型）　**产物**：`packages/cli` → `@innate/fe-cli`（bin `fe`）
- **对应目标**：[G5](../overview.md#g5-打包与部署脚本化)

---

## 目的

把"发现插件 → 生成聚合文件 → 产出可部署产物 → 校验契约"这套动作**脚本化**，让 shell 不再手写模块清单、不再手工维护 CSS 导入顺序。

这是 [G5](../overview.md#g5-打包与部署脚本化) 的核心交付：脚本以 **TypeScript + Bun** 实现，放在 `innate-fe-base` 内。

---

## Context

### 为什么需要生成器

三方都独立收敛到同一个结论：**模块清单和样式顺序不应该手写**。

| 仓库 | 现状 | 问题 |
|------|------|------|
| `cyacle` | `plot app apply` 生成 `vineModules.gen.ts` + `vineStyles.gen.css` | 机制正确，但绑定 plot（Go 工具链），本机无 plot 则 `router.ts` 的 import 无法解析 |
| `innate-wip` | 手写 `plugins[]` 数组 | 需人工与 `site-features.ts` 对齐，已知出现"死 flag"脱节 |
| `innate-fe-base` | 部分 codegen（`scene-catalog` 的 `generate:specs`）+ 手写 showcase registry | 需人工与 `packages/ui/src/index.ts` 对齐 |

### 可借鉴的生成物形态（cyacle）

`change.web.md` 定义的产物：

```ts
// vineModules.gen.ts
import { webDomain as ProjectDataWebModule } from '@carbonnt-cyacle/web-project-data'
import { webDomain as UicWebModule } from '@carbonnt-cyacle/web-uic'

export const webModules = [ProjectDataWebModule, UicWebModule] as const
```

```css
/* vineStyles.gen.css —— 顺序固定：base → domains → app */
```

设计约束（原文）：`main.tsx` **只 import 这一个 css 文件**；顺序固定，避免 "TS import 顺序与 CSS import 链路交错"；生成文件禁止手改。

### 约束与决策

- **运行时选 Bun**（[G5](../overview.md#g5-打包与部署脚本化) 要求）。仓库根已有 `bun.lock`，说明 Bun 已在本项目出现过。
- **生成物选择提交入仓**。cyacle 把生成物 gitignore，代价是"不先跑工具就无法 typecheck"（本机实测 `.cache/`、`vineModules.gen.ts` 全部不存在）。本规划选择**提交**，并在文件头写 `DO NOT EDIT` + 生成命令。
- **幂等是硬要求**：同一输入连跑两次，产物字节级一致（便于 CI diff 检测）。

## 实现方式

### 1. 包骨架

```
packages/cli/
├── package.json        # name: @innate/fe-cli, bin: { fe: "./src/bin.ts" }
├── tsconfig.json
├── src/
│   ├── bin.ts          # CLI 入口（参数解析 + 子命令分发）
│   ├── commands/
│   │   ├── gen.ts      # 扫描 + 生成聚合文件
│   │   ├── build.ts    # 独立打包（T07 落地，本任务留骨架）
│   │   └── verify.ts   # 契约校验（T09 落地，本任务留骨架）
│   ├── scan.ts         # 扫描 domain / plugin 包
│   ├── emit.ts         # 写文件（统一处理 DO NOT EDIT 头 / 幂等 / 格式化）
│   └── paths.ts        # 仓库根、workspace 目录解析
└── tests/
    └── gen.test.ts
```

```jsonc
// packages/cli/package.json
{
  "name": "@innate/fe-cli",
  "private": true,
  "type": "module",
  "bin": { "fe": "./src/bin.ts" },
  "dependencies": { "@innate/plugin-contract": "workspace:*" },
  "devDependencies": { "@innate/tsconfig": "workspace:*", "typescript": "^7" },
  "scripts": { "typecheck": "tsc --noEmit", "test": "bun test" }
}
```

根 `package.json` 增加转发脚本：`"gen": "bun run --filter @innate/fe-cli fe gen"`。

### 2. 插件发现规则（必须有确定性的约定）

扫描 `domain/*/package.json` 与 `apps/*/package.json`，认定一个包是插件当且仅当：

1. `package.json` 中存在 `"innatePlugin"` 字段（对象），**或**
2. 包内存在 `src/web/index.ts` 且导出了名为 `webDomain` 或 `pluginManifest` 的符号

`innatePlugin` 字段用于声明元数据（避免运行时 import 才能拿到）：

```jsonc
{
  "name": "@innate/domain-writing",
  "innatePlugin": {
    "id": "writing",
    "kind": "domain",              // domain | iframe-app
    "loadMode": "route",           // route | iframe
    "entry": "./src/web/index.ts",
    "styles": "./src/web/globals.css",
    "featureFlag": "writing"       // 对应 shell 的 site-features key，可空
  }
}
```

- `loadMode: "iframe"` 时必须有 `iframeSrc`（绝对路径，如 `/plugins/<id>/`）。
- 发现结果按 `id` 排序，保证生成顺序稳定（幂等的关键）。

### 3. `fe gen` 产出

| 产物 | 内容 |
|------|------|
| `apps/web/src/registry.gen.ts` | 静态 import 每个 `kind: domain` 的包的 `webDomain`，导出 `webModules` 数组；并导出 `pluginManifests`（从 `innatePlugin` 字段 + 可选 manifest 文件构造） |
| `apps/web/src/styles.gen.css` | 按 **base → domain → app** 顺序生成 `@import` |

产物格式（对齐 cyacle 形态）：

```ts
// AUTO-GENERATED by `fe gen` — DO NOT EDIT
import { webDomain as WritingDomain } from "@innate/domain-writing"
import { webDomain as MakingDomain } from "@innate/domain-making"

export const webModules = [WritingDomain, MakingDomain] as const
```

```css
/* AUTO-GENERATED by `fe gen` — DO NOT EDIT */
@import "@innate/ui/globals.css";
@import "@innate/domain-writing/globals.css";
@import "@innate/domain-making/globals.css";
@import "./globals.css";
```

### 4. 幂等与失败处理

- `emit.ts` 统一：写入前先 `readFile` 对比，内容相同则**不写**（避免 mtime 抖动触发 CI 误判）。
- 无插件时仍生成合法的空数组导出（`export const webModules = [] as const`），不报错。
- 扫描到 `loadMode: "iframe"` 但缺 `iframeSrc` → **报错退出（非 0）**，错误信息含包名与缺失字段。
- 扫描到重复 `id` → 报错退出。

### 5. build / verify 子命令

本任务只落**骨架**（参数解析 + `TODO` 分发），具体实现在 T07 / T09。但要把 CLI 的参数约定先定下来：

```
fe gen                    # 生成聚合文件
fe build <app|domain>     # 独立打包（T07）
fe verify                 # 契约校验（T09）
fe --help
```

## Verify

```bash
# 1. 类型与测试
pnpm --filter @innate/fe-cli typecheck
pnpm --filter @innate/fe-cli test

# 2. 幂等性（核心验收）
fe gen
git add -A && git diff --cached --stat          # 记录产物
fe gen
git diff --cached --stat                        # 期望：无新增/修改（除首次生成）

# 3. 生成物头部
head -n 1 apps/web/src/registry.gen.ts          # 期望：包含 DO NOT EDIT
head -n 1 apps/web/src/styles.gen.css           # 期望：包含 DO NOT EDIT

# 4. CSS 顺序
grep -n "@import" apps/web/src/styles.gen.css   # 期望：@innate/ui 在最前，./globals.css 在最后
```

**必须覆盖的测试用例**：

| # | 用例 | 期望 |
|---|------|------|
| 1 | 空 fixture（无插件） | 生成 `webModules = [] as const`，退出码 0 |
| 2 | 两个插件 fixture，扫描顺序被打乱 | 产物顺序按 id 稳定升序，两次运行字节一致 |
| 3 | 重复 id 的 fixture | 退出码非 0，错误含重复 id |
| 4 | `loadMode: iframe` 缺 `iframeSrc` | 退出码非 0，错误含包名与字段名 |
| 5 | 内容未变化时再次 `gen` | 目标文件 mtime **不变**（未写盘） |
| 6 | CSS 产物顺序 | `@innate/ui` 在首，app 自身 globals 在末 |

**完成标准**：6 条用例全绿；在真实仓库上跑 `fe gen` 两次，`git status` 第二次为空；`build` / `verify` 子命令存在且 `--help` 可打印（内部可为 TODO）。
