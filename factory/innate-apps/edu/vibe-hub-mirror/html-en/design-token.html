Design Token

You might say

Organize the main color, spacing, and radius as design tokens instead of repeating values in every component.

A design token is a named variable that centrally stores and reuses design values such as color, spacing, and typography.·A primary button color can be named color.brand.primary and a common gap space.16; components reference those names rather than each hard-coding a color or pixel value. Tokens help a shared rule stay consistent across a site, component library, or other interfaces when themes or brands change. They are not a synonym for every CSS variable and do not replace the design decision itself.

How design tokens preserve consistency

Name stable design decisions first: Tokens should express a role or scale such as primary brand color, danger color, card radius, or spacing step. A name explains why a value exists better than one hex color or pixel count.

Components reference one source: Buttons, links, and selected states read a shared token, so theme or brand changes can update centrally. For a one-off exception, first decide whether it is truly a new reusable rule.

What it is not

Design tokens are not the whole design system, and not every CSS variable deserves to become a token. Tokens store shared design decisions; components, layout, and content rules still need separate design. Naming a one-time patch as a token creates noise.
