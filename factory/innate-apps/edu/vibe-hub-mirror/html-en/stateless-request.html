Stateless Request

You might say

The table is still visible in the chat. Why does the AI not know what to do when I send only “continue”?

A stateless request is a model call that uses only what it receives this time and does not automatically retain prior input or results·If one request creates a table and the next contains only “continue,” the model does not know which table to continue. The product may save the table and chat, but it must include the current goal, table, and relevant result again.

How the next request gets the earlier table

The model receives only this request: If the second call contains only “continue,” it lacks the earlier table, goal, and result.

The product retrieves saved material: The application can recover the current table, unfinished goal, and prior result from its records.

The new request includes what is needed: The application sends that material with “continue,” giving the model enough context this time.

What people often confuse

Stateless does not mean the product cannot save data. Conversation history may be stored, but each model call still sees only what was actually sent.
