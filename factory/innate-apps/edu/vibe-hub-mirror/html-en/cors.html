CORS

You might say

The browser blocked this page's API request. Check whether CORS is not allowing this site.

CORS is the browser security mechanism that lets a page read a cross-origin response only after the server explicitly permits it.·When a page on app.example.com requests api.example.com, the server must allow that page origin in its response before the browser gives the data to script. It protects cross-origin reads in browsers; the server still decides whether an API can be called and whether a user has permission.

Where CORS sits in the request path

An origin comes from the address: A different protocol, domain, or port can mean a different origin. A local page at localhost:3000 calling localhost:4000 is a common cross-origin case too.

The server declares the allowed scope: Before the browser exposes a response, it checks CORS response headers. A server should allow the real sites, methods, and credentials needed—not every origin just to remove an error.

What it is not

CORS is not authentication, login, or database authorization. Even when a browser may read a response, the server must verify identity and permission. Conversely, a signed-in user can still see a CORS error when the server did not allow the current page origin.
