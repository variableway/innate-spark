HTTP

You might say

When I click a button, what actually happens between the browser and the server?

Send a request and receive a response over the web·HTTP is the request-response protocol browsers and APIs use. A request includes a method, URL, headers, and sometimes a body; the response includes a status, headers, and content. Methods and status codes should match what actually happened.

When NOT to use it

  • Use a successful status code for a failed operation
    /login?pwd=123456The password entered browser history and server logs.
  • Change data with a request intended only for reading
    GET/api/list
    A GET request body has no universal meaning; do not depend on how a server handles it.
  • Retry every failed request without limits
    POST/api/order ×3
    Repeated requests can create multiple orders; the server also needs idempotency keys or unique constraints as a safeguard.
  • Log sensitive headers or bodies carelessly
    Changing the API format based on assumptions without checking the actual request.
Anatomy
POST /api/login HTTP/1.1
Host: api.vibeui.dev
Content-Type: application/json{ "email": "you@example.com", "pwd": "••••••" }
The request method describes the action: GET, POST, PUT, PATCH, or DELETE.
The URL identifies the destination; the path and query narrow down the resource.
Headers carry metadata such as the content type, credentials, and request origin.
The optional body carries data, commonly with POST, PUT, or PATCH. Content-Type and the API contract define its format.

Quick decision

HTTP vs HTTPS: what is the difference?

Use HTTPS for public sites and production APIs. It keeps HTTP's request-response rules while TLS protects the connection.

Decision pointHTTPHTTPS
What it isThe standard request-and-response rules between client and server.Standard HTTP traffic carried over an encrypted TLS connection.
Data in transitPlain text; network observers along the path can read or modify data.Encrypted in transit; protected from eavesdropping and silent tampering.
When to useLocal development and offline testing (e.g., http://localhost).Public deployments, user authentication, payments, and production APIs.
Submitting a production login form

Over plain HTTP, network devices along the route may read the password. HTTPS encrypts the connection and verifies the server's identity, but it cannot fix server vulnerabilities or replace authorization and input validation.
