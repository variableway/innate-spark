DOM

You might say

A task appears after I click Add, but it is not in the source HTML. Help me confirm what was inserted at runtime.

The DOM is the node tree the browser uses to represent and modify a web document.·For example, the source HTML may contain one task while a click adds another to the page. A script created a node and inserted it into the runtime DOM. That change affects the current page, but whether it survives a refresh depends on separate persistence in a backend or browser storage.

Adding a DOM node changes the current page, but surviving refresh depends on real persistence.

Why the current page can differ from the source file

The browser parses the document first: The browser reads HTML and organizes its elements, text, and attributes into a hierarchy of nodes that begins the page render.

A script can change the tree: After a click, JavaScript can create, remove, or change nodes, so the DOM in Elements may differ from the original HTML file.

What it is not

The DOM is the browser's current runtime document tree, not the initial HTML file and not a database. A task inserted into the DOM may disappear on refresh; retaining it across refreshes, devices, or users requires separate data storage. Modern frontend frameworks (like React or Vue) help manage DOM updates—you describe what the interface should look like, and the framework automatically calculates which nodes need to change. AI-generated React code rarely uses document.createElement, because the framework manipulates this tree behind the scenes for you.
