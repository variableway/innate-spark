Web Hosting

You might say

Confirm that this project has hosting that can continuously serve the site, then deploy it publicly. Do not treat localhost as live.

A service that continuously stores and serves website files or a running environment·A page that works locally still needs a public environment that can serve it continuously. Web hosting provides that environment for files or a running service; deployment is the one-time action of publishing a version into it. They are related but not the same.

What hosting and deployment each do

Hosting is the persistent environment: It stores static files or keeps a request-serving service running. When people use a public address, the environment returns the page or service result.

Deployment is the action that puts a version there: A deployment publishes one build or code version into the hosting environment. A successful build or a domain alone does not prove the public site serves the right version.

What it is not

Hosting is the long-lived environment that serves a site; deployment is a version-release action; a domain and DNS direct an address to a target. Hosting does not automatically provide a custom domain, database, or correct version, so verify with a public request.
