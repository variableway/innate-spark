用户问题“工单 #1024 谁负责？”

用户只说想查什么；AI 应用负责接住问题，并决定这次可以使用哪些连接。

MCP 统一工具怎样被发现和调用；真实数据与访问权限仍由外部系统负责。

一次 get_ticket 查询里，谁负责什么

配置与服务公开查询工具：在 AI 工具设置中填入服务器命令即可启用 MCP 服务。服务（Server）告诉应用自己具备哪些工具（如 get_ticket）以及需要什么参数。

AI 应用发起调用：模型提出 get_ticket({ id: 1024 })，应用中的 MCP Client 按协议把请求交给工单服务。

工单系统返回真实记录：工单系统检查测试账号只能读取，随后返回 #1024 的负责人；MCP 不会替它保存数据或判断权限。

容易混淆的地方

MCP 不是 get_ticket 工具，也不是工单服务本身。它规定应用与服务怎样发现能力和交换调用；账号权限、真实工单和高风险确认仍由应用及工单系统负责。
