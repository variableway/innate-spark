02 · 安装与使用

Skill 怎么安装

把仓库地址和 Skill 所在路径一起发给 Agent，让它完成下载、安装和检查。

你把这两行发给 Agent
https://github.com/oil-oil/vibe-hub-skill
帮我安装这个仓库里的 skills/vibehub Skill。
→
安装完成skills/vibehub/Agent 已经可以使用

Skill 也可以来自：GitHub、SkillHub、别人发来的本地文件夹

安装以后怎么用直接告诉 Agent 你要做什么

你可以直接点名 Skill，也可以只描述任务，让 Agent 判断是否需要使用。

你例如
使用 VibeHub，帮我学懂 Git Branch。

不同 Agent 保存 Skill 的位置可能不同，安装时让当前 Agent 自己确认。

03 · 作用

Skill 的作用

Skill 主要解决两件事：把重复做法固定下来，再把需要的知识和文件交给 Agent。

  3. 检查后交付

05 · 测试

Skill 怎么测试

让有 Skill 和没有 Skill 的 Agent 做同一个任务，再直接比较结果。

相同模型 · 相同输入 · 相同任务把 12 条项目记录整理成周报
没有 Skill

只提供任务和原始记录，让 Agent 自己决定步骤。

结果容易变化
加载 Skill

提供同样的任务和记录，同时让 Agent 使用周报 Skill。

结果更容易复现
结果过程稳定性消耗

支持 Sub-agent 时可以并行测试；不支持时，就开两个独立对话。

06 · 最佳实践

Skill 的最佳实践

Skill 是给 AI 读的，所以要短、清楚、容易执行。

SKILL.md
name: video-publisherdescription: 发布视频并检查平台要求。用户准备发布、检查尺寸或生成封面时使用。按顺序完成检查、生成和发布前确认。

描述写清楚：说明这个 Skill 做什么，以及什么任务应该使用它。

容易混淆的地方

Skill 提供做事方法和相关文件，不会自动获得账号、平台或其他外部系统的权限。

选择题选择一个你认为最合适的答案

团队每周都让 Agent 按同一规则生成发布说明，还要复用脚本和模板。怎样减少重复教学？

你可以这样告诉 AI Agent

“

请把每周发布说明流程整理成 Skill：SKILL.md 写清触发条件、输入、步骤和验收，脚本与模板放在对应目录。只保留稳定规则，不复制临时聊天；用一份真实改动验证可重复执行。
