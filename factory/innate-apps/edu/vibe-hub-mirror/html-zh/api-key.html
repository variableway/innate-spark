API 密钥API Key

你可能会说

帮我接上大模型 API，把 API Key 放在环境变量中读取，千万不要硬编码在代码里。

供应用程序向接口服务表明身份、验证调用权限并追踪资源用量的访问凭证。·例如给网页接上 AI 能力：程序从环境变量读取 API Key，并随请求交给服务验证。服务通常把权限和用量记到 Key 所属的账户、项目或应用，而不一定代表某个具体的人。Key 一旦泄露，别人可能消耗额度或访问数据；不要把它写进代码、仓库或聊天记录，发现泄露后立即吊销并更换。

Key 是程序的门禁卡，不是给人记的密码创建时通常只完整显示一次；泄露第一反应是吊销。
它是干什么的

程序版的门禁卡：你的网页调用 AI 服务时，请求里带上这串字符，服务验证它所属的账户、项目或应用，再按对应权限处理请求和记录用量。

在服务商后台创建：去提供服务的网站（比如 AI 服务商）创建 Key，通常只在创建时完整显示一次，要当场保存好。

泄露就吊销：发现 Key 出现在不该出现的地方，第一件事是回后台吊销它，再创建新的——比追查谁看到过更快更稳。

容易混淆的地方

API Key 和 Auth Token 都可能用于程序鉴权，具体名称、有效期和权限范围由服务决定，不能只看名字判断它是否短期或安全。它们都不该出现在代码仓库或聊天记录中；与 AI 协作时可以说「Key 从环境变量读取，只引用变量名」。
