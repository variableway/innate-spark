Sub-agent

你可能会说

大任务能不能拆给几个帮手同时干，最后汇总给我？

由主 Agent 调度、专注处理特定独立子任务的专项执行单元。·例如上线前，主 AI 可以让一个帮手检查页面文字，另一个检查手机布局，再汇总两边结果。它不会自动知道全部背景，任务范围、可用权限和需要交回什么，都要提前说明。

一次发布审查怎样被拆成三个独立检查

主 Agent 写清每个子任务的目标、输入、权限和交付格式，避免多个 Agent 做同一件事。

Sub Agent 适合边界清楚、可以独立验收的工作；拆分本身也会带来协调成本。

主 Agent 怎样委派、隔离和汇总

先拆出有边界的任务：主 Agent 把安全、测试或文档检查分别交给 Sub-agent，并写清可读写范围、完成标准和返回内容。

各自在独立上下文工作：每个 Sub-agent 可以专注读取资料和使用工具，详细日志留在自己的线程，只返回与主任务有关的证据和结论。

最后由主 Agent 协调结果：主 Agent 等待所需结果，处理重复或冲突，再结合原始目标形成统一结论；写同一文件的任务通常需要串行或明确分工。

容易混淆的地方

Sub-agent 不是跨平台统一标准：不同产品对上下文继承、权限、并发、线程和生命周期有不同定义。它也不等于 Skill；Skill 是可加载的任务知识，Sub-agent 是实际执行被委派任务的 Agent。

选择题选择一个你认为最合适的答案

上线前要检查无障碍、接口错误处理和测试缺口，三项都只读代码并能独立给出证据。怎样安排更合适？

你可以这样告诉 AI Agent

“

请把这次上线前审查拆给三个只读 Sub-agent：一个看无障碍，一个看接口错误处理，一个找测试缺口。每个都要给出文件位置和证据，不要改代码。等三个结果都回来后，合并重复项，按风险列出最终清单；需要修改时先让我确认。
