模型提供方Provider

你可能会说

配置里的 Provider 和 Model 分别指什么？我的请求最后会发给谁？

Provider 是你通过它访问 AI 模型的服务平台与基础设施实体。·模型厂商、云平台、聚合网关，甚至本地模型服务，都可能在工具里作为 Provider。它负责接收请求并提供模型访问，通常还处理凭证、限流或计费，但不一定训练或直接运行底层模型；要结合 Base URL、Key 签发方和账单方判断请求实际经过谁。

一次请求怎样通过 Provider 变成模型结果
1 · 本地配置config.toml
config.toml
1provider = "openrouter"
2model = "deepseek-v4-flash"
3base_url = "https://openrouter.ai/api/v1"

工具先读取要通过谁调用，以及要使用哪个模型。

→按配置发送
2 · 实际请求OpenRouter API
POST/chat/completions
https://openrouter.ai/api/v1model: deepseek-v4-flash

请求实际到达 OpenRouter；模型名只是这次调用的目标。

→返回结果
3 · 可观察结果200 OK
Terminal
$ OpenRouter
  model: deepseek-v4-flash
  answer: 返回按钮代码

Provider 把模型生成的结果返回给工具。

Provider 是请求链路中的服务平台；Model 是这次请求选中的具体模型。

Provider 和 Model 的区别

用厨师来理解 Provider：你想找厨师做一道菜：Model 是真正做菜的厨师，Provider 是提供厨师和服务的餐厅或平台，API 是你向餐厅下单的窗口，API Key 是证明你有权点餐的会员卡，Base URL 是餐厅的地址。所以，Provider 就是你通过谁来使用 AI 模型。

Provider 和 Model 在配置中分别表示什么：配置 provider: openai、model: gpt-5，表示通过 OpenAI 使用 gpt-5；配置 provider: deepseek、model: deepseek-chat，表示通过 DeepSeek 使用 deepseek-chat。可以简单理解为：Provider 是“谁提供服务”，Model 是“具体使用哪个模型”。如果配置里的 Provider 写成 openai-compatible，通常只说明服务平台接受类似 OpenAI 的请求格式，并不代表请求一定发给 OpenAI；还要结合 Base URL、API Key 发放方和账单方判断真正的服务平台。

换 Provider 后，价格和体验也可能变化

即使选择同一个 Model，不同 Provider 的价格、速度、稳定性、上下文限制、图片或工具调用支持，以及数据处理规则也可能不同。排查配置时把四项放在一起看：Provider 是通过谁调用，Model 是选哪个模型，Base URL 是请求发到哪里，API Key 是使用谁签发的凭证。
