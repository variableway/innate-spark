API 代理 / 中转站API Proxy

你可能会说

我换成中转地址后请求能成功了，但提示词、文件和 Key 会经过谁？帮我把链路检查清楚。

API 代理是位于客户端和上游 API 之间，代为接收和转发请求与响应的中间服务。·例如 AI 工具把请求发给中转站，再由它转给模型提供方；结果也沿同一路径返回。中转站可以负责鉴权、路由或统一入口，但不代表模型运行在那里。提示词、文件片段和凭证可能经过它，因此使用前要核对运营主体、隐私政策、数据留存和 Key 的签发方。

为什么中转站有隐私风险

请求和返回都会经过中转站：请求中的提示词、上下文、文件片段，以及可能随请求发送的凭证，会先到达中转站；Provider 返回的内容也会经过中转站后再到工具。

公开信息只让服务更容易核验：有公开运营主体、官方文档和服务条款的平台，更容易检查服务边界、计费和隐私政策，但这不等于它天然可信。只要请求经过第三方，就要继续核对数据留存、密钥处理和上游服务。

来源不明的服务风险更高：有些非正规中转站可能通过号池、反向代理等方式拼接调用资源；如果它记录请求、篡改返回或注入内容，AI 工具通常无法替你审核它的数据处理行为。因此不要把密钥、源码和敏感业务数据交给来源不明的中转站。

中转站不是模型 Provider

API 代理通常只负责接收、转发和返回数据，不等于它自己训练或运行模型；本地 VPN 或网络代理也不一定理解 API 协议。换了地址只能改变网络路径，不能自动保证匿名、安全、结果质量或上游可用性。
