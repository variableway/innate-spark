Agent 运行框架工程Harness Engineering

你可能会说

同一个 AI 有时做得很好，有时总在同一个地方犯错，除了换模型还能改什么？

Agent 运行框架工程是把项目知识、工具、状态、权限和检查做成 AI Agent 可用工作环境的工程实践。·例如前端 Agent 交付了看似完整的页面，独立评审器会用浏览器实际点击主流程，再把失败步骤和截图送回下一轮。它改造的是模型周围的工作条件，不是把提示词写得更长。

什么结果才算改善真人可以完成主流程

只有真实页面能操作、评审检查通过，这轮任务才结束。

截图只能证明页面能显示；会实际操作页面的评审器，才能证明体验是否真的可用。

同一种失败反复出现时，应补能暴露、记录并纠正它的环境支持，而不是只把提示词写得更长。

三个案例分别解决了什么问题

页面能显示但不能操作：独立评审器用浏览器实际点击、截图并检查完整流程。失败动作和具体批评会回到下一轮，而不是让生成页面的 Agent 自己给自己打分。

换一轮就重复旧工作：功能清单、进度文件、启动脚本和 Git 提交把状态留在项目里。下一轮先读记录并跑基础检查，再选择一个未完成项继续。

代码逐渐违反原有规则：简短项目地图帮助 Agent 找入口，结构化文档提供细节，自定义 lint 和结构测试把架构要求变成会失败的规则，并指出修正路径。

容易混淆的地方

Agent 循环负责一次运行何时继续、暂停或停止；Harness Engineering 改造的是循环所在的环境。它不能保证模型永不犯错，但能让重复错误更早暴露、被保存成证据，并在下一轮得到纠正。装上一个 SDK 或写一份很长的说明，都不等于已经有可靠的 Harness。
