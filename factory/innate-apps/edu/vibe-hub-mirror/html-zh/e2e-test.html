端到端测试提供的核心质量凭证

从用户入口开始，而不是从内部函数开始：测试点击、输入、跳转和最终页面，使真实用户会经过的关键路径有一份可重复证据。它适合注册、支付前确认或创建内容等跨多层任务。

关键路径要少而有代表性：完整流程通常较慢、受环境影响更多，因此先覆盖最重要的成功和高风险失败路径。更细的规则仍应交给单元和集成测试更快地定位。

容易混淆的地方

端到端测试不等于“所有测试都在浏览器里点一遍”。它验证少量关键用户旅程；只有 API 或单个组件的检查能更快定位问题，但不能替代完整流程证据。
