先说明角色、目标和进入场景：访客从服务页进入预约。

一张 User Flow 聚焦一个角色的一项目标：主路径之外，失败和恢复路径也要画出来。

User Flow 怎样把一项目标变成可检查的路径

先固定用户、目标和起点：说明是谁从哪个入口开始、想完成什么，以及什么结果才算结束；目标含糊时，路径很容易无限扩张。

连接有意义的动作：按顺序放入推动任务前进的页面、操作和决定，例如选择时段、提交资料和确认预约，不必记录每一次滚动或点击。

补上关键分支与恢复：标出无可用时段、资料错误或提交失败时用户会看到什么、能怎样返回主路径，避免只画理想成功路线。

容易混淆的地方

User Flow 不等于 sitemap、wireframe 或 customer journey：sitemap 表达页面与内容层级，wireframe 表达单个界面的元素和布局，customer journey 跨多个触点记录更完整的经历、感受与认知；User Flow 只聚焦一个目标在产品内的关键动作和决策分支。
