用户用例怎样描述系统行为

围绕一个参与者目标：先明确谁要完成什么，以及什么事件触发这次交互，避免把多个无关功能塞进一个用例。

交替写动作和回应：每一步都说明参与者做什么、系统显示或改变什么，让外部行为可以被讨论和检查。

补上重要例外：超期、资料不完整或重复提交等条件会改变结果，需要写清系统怎样结束或帮助用户恢复。

容易混淆的地方

用户故事 User Story 简短说明用户、目标和原因；用户用例 Use Case 展开参与者与系统的交互；用户流程 User Flow 用路径图呈现页面和决策分支；测试用例 Test Case 再用具体输入和步骤检查其中一条规则。
