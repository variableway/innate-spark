项目规则告诉 Agent 在当前目录怎样工作；它不是模型本身的永久记忆。

项目规则负责什么

一份规则文件包含约定与禁止项：典型的 AGENTS.md 或 .cursorrules 包含：(1) 项目概述与技术栈；(2) 文件结构与风格约定；(3) 禁止行为（如私自提交代码、删除数据库）；(4) 验收方式。建议先写 5-10 条最容易踩坑的规则。

自动成为多轮任务的上下文：工具读取项目规则后，模型会把它们带入当前任务，减少每次重复说明要求。

规则可随仓库共享，但绝不能放密钥：团队规则通常随 Git 提交；真实 API 密钥和个人绝对路径不应写进规则文件，密钥应交给环境变量。

项目规则不能代替硬性检查

项目规则是给 Agent 的指导，不是客户端权限策略，也不会像编译器、Linter 或测试那样自动证明结果正确。敏感操作仍要由权限边界控制，修改结果仍要用项目已有检查和人工判断验收。
